# Dovetail 0.1.4

## Exact JSON integers

JSON now preserves every Int64 value through parsing, encoding, and derived
record codecs, including `9007199254740993` and both Int64 extrema. Integer tokens
are parsed directly from decimal digits with checked arithmetic; they never pass
through Float64. Ordinary Int64 fields need no custom wrapper.

`Json.Number` now contains a `JsonNumber` with either Int64 or finite Float64
storage. Its helpers provide exact `fromInt32`/`fromInt64` construction, checked
`toInt32`/`toInt64` conversion, checked `fromFloat64`, and `toFloat64`, `parse`, and
`format`. Integer-to-Float64 conversion may lose precision.

Integer tokens outside Int64 fail during parsing with `JsonError.OutOfRange("Int64")`.
Int32 narrowing returns `OutOfRange("Int32")`. Numeric errors propagate through
nested arrays and objects. Malformed numeric tokens and incomplete collections
are rejected explicitly.

## Breaking changes and migration

- Replace `Json.Number(float)` with checked `JsonNumber.fromFloat64(float)` followed
  by `Json.Number(number)`. Prefer `value.toJson()` for ordinary integers.
- Pattern matches on `Json.Number(number)` now receive JsonNumber. Use its conversion
  helpers rather than treating the payload as Float64.
- Integer decoders reject every float node with `TypeError("Integer", "Float")`,
  including mathematically integral `1.0`, `1e3`, and `10e-1`. Producers of integer
  fields must use integer syntax. This also rejects fractional tokens that round
  to an integral float. The legacy `NonIntegralNumber` error remains declared but
  is no longer returned by primitive decoders.
- Integer tokens outside Int64 no longer become approximate floats. BigInt,
  integers above Int64.MAX, and exact-decimal storage are unsupported.
- Float serialization retains a decimal point or exponent so whole-valued floats
  keep their numeric category after parsing. Numeric spelling is not preserved.
- Float parsing now supports accurate binary64 rounding, signed zero, and
  subnormals. Underflow becomes signed zero; overflow returns
  `OutOfRange("finite Float64")`.
- `JsonNumber.fromFloat64` rejects NaN and infinities with a typed error. The
  infallible `Float64.toJson()` convenience encoder maps them to null, including
  derived fields. Use the checked constructor when explicit failure is required.

## YAML and cross-format configuration

YAML already preserves integer tokens exactly and checks Int32 narrowing. Its
integer decoders continue rejecting decimal/exponent float nodes. Signed decimal,
unsigned hexadecimal/octal syntax, and typed overflow diagnostics retain their
existing behavior. The float exponent counter is widened to prevent arithmetic
wraparound on extremely large inputs.

Regression coverage verifies YAML text → derived record with Int64 fields and
lists → JSON text → record, including extrema, both signs around 2^53, and YAML
radix integers. YAML has no encoder. See the [integer handling audit](../json-integer-design.md)
and [library guide](../../website/content/book/22-stdlib.md) for details.

## Distribution and documentation

Published GitHub releases now publish the packaged VS Code extension to the
Visual Studio Marketplace, in addition to compiler packages and downloadable
release assets. The repository requires the configured `VSCE_PAT` secret.
The website adopts the wooden Dovetail logo, and the README links to the published
language documentation.

## Version compatibility

The compiler and VS Code extension are both version **0.1.4**. Update
`compiler-version = "0.1.4"` in application and dependency manifests; the compiler
requires an exact match. Use the matching standard-library revision and refresh
installed AI guidance with `dovetail ai install` after upgrading.
